Agent Deployment Playbook

An agent directory becomes a governed release through compilation, evidence binding and independent runtime qualification. The developer supplies business logic and declared intent. The platform supplies identities, durable coordination, confined execution, approved routes and operational controls. Automation removes repetitive work; it does not silently convert observed behavior into permission or promote untested policy into production.

Selected baseline. Framework-neutral Python contracts, explicit Temporal activities and workflows, cloud-neutral Kubernetes, and general enterprise controls. The target architecture below defines the integration acceptance criteria. The toolkit chapter records what has actually been executed, rendered or live-tested.
Technical implementation review. Continue with the integration deep dive for native configurations, credential ownership, adapter contracts and readiness gates; the incident triage walkthrough follows one package through proposal, approval, effect and revocation.

3.1 Deployment inputs and the immutable release bundle

The initial repository provides an actual locked OCI worker build and a separate Kubernetes qualification fixture. Follow the worker build and deployment guide for its entrypoint, configuration, digest chain and reproduced workflow. This implementation is a read-only baseline; the target release bundle below adds independent trust and governance requirements.

The release compiler consumes a validated agent manifest, a source revision, a built image digest, the organization policy boundary, approved capability requests, evaluation evidence, and a versioned platform profile. Each input has an owner. The developer cannot replace the organization boundary, approve their own exception or nominate an arbitrary evaluator result as trusted release evidence. A release controller must independently verify provenance from its configured CI identities.

A package is portable; a deployment is environment specific. Keep logical capability names such as documents.search in agent code. Resolve those names to a tenant-aware backend, workload identity, schema and approved endpoint in the environment binding. Do not embed production network addresses, vault paths or model API keys in portable source. The compiler should fail on unresolved capabilities instead of inventing permissive defaults.

Sign an envelope containing these digests rather than signing unstructured folders. Verification binds a specific subject digest to an approved signer identity, workflow and source revision. Signatures prove origin and integrity; they do not prove safety. A production admission rule must check signature trust, required predicates, freshness, environment and revocation status. Keyless signing still requires an issuer/subject allowlist and verification policy. Use a transparency record or approved internal equivalent according to your organization’s supply-chain design.

3.2 Compile permission from intent, evidence and a boundary

Policy synthesis is a constrained proposal process. Static analysis produces capability hints; SDK/MCP introspection supplies tool schemas; dynamic profiling reveals exercised behavior and denials. None establishes business authorization. The approved capability request states what the agent is allowed to do; the organization boundary states what the platform may permit; the environment binding identifies how that authority is enforced. The target effective permission is their intersection, with explicit deny precedence and time-bounded exceptions.

Normalize events into a schema with agent ID, release/image digest, pod UID, container ID, process ancestry, operation type, destination/resource, outcome and collection timestamp. Reject mismatched workload identity; retain event-loss metrics and collector health. Never append an entire trace to an allowlist. Deduplicate repeated calls, distinguish attempted from successful operations, and retain supporting scenario IDs. A call seen only in an adversarial test is evidence that a denial should work, not a reason to grant it.

Profile delta reports show “declared but unobserved,” “observed and declared,” “observed but undeclared” and “unsupported/unclassified.” The first can indicate missing coverage; the third can indicate an undeclared dependency or compromise. Both require triage. The compiler may scaffold a narrow candidate rule for review; it must never auto-accept permission expansion from an agent or evaluator’s own output. Rollout impact simulation helps discover required behavior without treating denial volume as proof of correctness.

# Current v0.1 CLI: produces a proposal, not an executable vendor policy
zetra profile integrations/evidence/tetragon-normalized-events.jsonl \
  --agent tetragon-fixture \
  --image docker.io/library/alpine@sha256:4b7ce07002c69e8f3d704a9c5d6fd3053be500b7f1c69fc0d80990c2ad8dd412 \
  --output build/policy-candidate.json

# Native Kubernetes resources start at zero replicas.
zetra render examples/knowledge \
  --image registry.example/agents/knowledge@sha256:… \
  --namespace agent-staging \
  --gateway-namespace agentgateway-system \
  --gateway-label app=agentgateway \
  --evidence build/eval.json \
  --output build/deployment.yaml
No automatic completeness claim. A passing suite exercises a sample of behavior. A generated policy may omit rare legitimate operations or admit a harmful operation observed during tests. Safe activation requires reviewed intent, negative enforcement tests and a rollback path.

3.3 Kubernetes is the deployment substrate and an enforcement boundary

Build the worker image from pinned dependencies, run a nonroot UID, drop capabilities, disable privilege escalation, use a read-only root filesystem and the runtime-default seccomp profile. Mount bounded temporary scratch space at an approved location. Do not grant host networking, host PID, host paths, arbitrary devices or privileged containers to ordinary agent workloads. The platform’s privileged node agents belong in a separately administered trust domain.

Create a dedicated ServiceAccount and disable automatic token mounting unless an explicit authenticated platform connection requires a projected token. Scope a projected token to the receiving audience and short lifetime; it is a workload credential, not a universal model, database or business-user credential. Kubernetes RBAC should grant no rights by default. Namespace isolation is an organizational aid, not a strong tenant boundary by itself; high-consequence workloads may need separate worker pools or clusters.

Install default-deny ingress and egress, then grant narrowly scoped access to the approved gateway and required control services. Namespace and pod selectors in the same NetworkPolicy peer form a combined condition; use both to avoid matching every pod in a trusted namespace. Port restrictions must match the actual gateway listener. DNS is a deliberate channel: use the approved resolver, deny direct external DNS and test IP-literal, alternate protocol and IPv6 bypasses. NetworkPolicy enforcement depends on the selected CNI and policy model. Native policies are additive and do not authorize HTTP methods or tool names. Validate actual denied connectivity; resource presence alone is insufficient. Kubernetes NetworkPolicy reference.

The v0.1 renderer withholds activation by emitting zero replicas. Its gateway egress template is a starting point, not a complete Temporal/telemetry environment binding. A platform-reviewed binding must add control-plane peers and the correct listener ports before activation. Do not scale the render merely because schema validation passed. The target release controller additionally requires policy-ready acknowledgements from each mandatory adapter and an effective-policy epoch consistent with the release.

# Native Kubernetes security context, illustrative platform baseline
spec:
  serviceAccountName: knowledge-assistant
  automountServiceAccountToken: false
  securityContext:
    runAsNonRoot: true
    runAsUser: 10001
    seccompProfile: {type: RuntimeDefault}
  containers:
    - name: agent
      image: registry.example/agents/knowledge@sha256:…
      securityContext:
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities: {drop: [ALL]}
      resources:
        requests: {cpu: 100m, memory: 128Mi}
        limits: {cpu: "1", memory: 512Mi}

Mutating admission can inject approved endpoint bindings, telemetry setup or sandbox launch parameters. It cannot guarantee that arbitrary Python becomes durable or that encrypted network traffic becomes visible. Keep mutation deterministic, idempotent, versioned and observable; avoid assumptions about container array positions or existing environment arrays. A separate validating admission layer rejects omitted controls, digest mismatch, unauthorized exceptions, unsuitable nodes or missing qualifications. Validate the final object after mutation. Fail-closed rules need an operational emergency path whose use is explicitly audited. The baseline security context follows Kubernetes Pod Security Standards; Zetra-specific binding rules require a platform implementation.

The portable factory gets narrow typed capabilities. In-process checks help developers but do not withstand arbitrary code execution; the sandbox and network boundary must enforce the same limits.

3.4 Tetragon: selected kernel evidence and tested response

Tetragon supplies process and selected kernel-boundary evidence. It complements application authorization; it cannot determine whether an LLM’s answer is truthful or a permitted database update is appropriate. Install the daemon through a separately reviewed platform change and pin the chart, image, CRD and runtime-hook configuration. Qualification records node architecture, kernel/BTF features, container runtime, available hook symbols and event-loss behavior. A heterogeneous cluster needs qualification per supported node class.

Use scoped observation policies in an isolated evaluation environment. Three probes do not record every syscall. Choose hook points for the specific behavior, declare argument types, verify emitted fields and correlate descendants as well as the parent process. Runtime lifecycle filtering must be explicitly configured and tested. A policy present in the API is not proof that the node loaded it before workload startup. Tetragon runtime hooks, TracingPolicy schema.

# Documented observation shape; validate kernel/CRD compatibility live.
apiVersion: cilium.io/v1alpha1
kind: TracingPolicyNamespaced
metadata:
  name: zetra-observe-connect
  namespace: agent-ci
spec:
  podSelector:
    matchLabels:
      zetra.dev/agent: knowledge-assistant
  kprobes:
    - call: tcp_connect
      syscall: false
      args:
        - index: 0
          type: sock

This example observes a selected TCP hook; it grants or denies no capability. Enforcement templates need independent tests for hook semantics, selectors, action availability and races. Do not use a matchBinaries example as proof that a newly requested executable is authorized. Interpret hook arguments in their declared context; a matchArgs index is not automatically a Python command-line argument. A post-event kill action can stop a process after an attempted operation; it is not universally a pre-operation authorization decision.

Prefer OS confinement and pre-operation controls for access that must never occur. Use Tetragon to detect unexpected processes, sensitive-path access, network behavior and policy drift, with tested responses appropriate to the hook. Avoid host-wide kill policies and automatic learning on production traffic. An interpreter allowlist still permits code running inside that interpreter, including dynamic Python execution. Combine kernel evidence with tool-level authorization and constrained filesystem/network capabilities.

3.5 OpenShell: confined execution and effective-policy verification

Production adoption gate. NVIDIA identifies the Kubernetes Helm deployment path as experimental. Local validation can evaluate it; enterprise production adoption requires an explicit maturity decision, pinned-release support assessment and compensating controls or an alternative supported sandbox. This playbook does not turn an experimental deployment into a production guarantee. Upstream Kubernetes setup status.

The OpenShell adapter resolves an approved runtime image and supported compute driver, starts the sandbox through the supported lifecycle, and constructs its filesystem/process/network policy. It must report the effective policy, including provider contributions and applicable global configuration. Zetra’s intended organization-and-agent intersection is a compiler responsibility: OpenShell global policy replacement behavior must not be mistaken for intersection semantics. Fixed filesystem and process changes require a new sandbox rather than an assumed hot reload. OpenShell policy behavior.

# Upstream shape; incomplete until required runtime paths are resolved.
version: 1
filesystem_policy:
  read_only: [/usr, /etc, /app]
  read_write: [/tmp/agent_scratch]
network_policies:
  approved_status_api:
    endpoints:
      - host: api.internal.example
        port: 443
        protocol: rest
        enforcement: enforce
        rules:
          - allow: {method: GET, path: /v1/status}
    binaries:
      - path: /usr/local/bin/python3.12

Use the schema and CLI belonging to the installed version, not the proposal’s sandbox.network.rules structure. Capture filesystem denials, direct-connect attempts, DNS behavior, alternate executables and provider binding. An allowed interpreter path means another program in that interpreter may share permission; do not treat it as a code-identity guarantee. Native TCP policy does not parse arbitrary database queries. Tool-name restrictions do not authorize tool arguments or business resources. Policy schema, Network rule semantics.

Advisor proposals remain untrusted suggestions. Keep automatic permission expansion disabled in governed environments. Where a prover is available, execute it against the approved boundary and parse structured result, reason, modeled domains and unsupported coverage. “Inconclusive” and “unsupported required domain” are release failures. A proof of modeled access containment is neither a proof of arbitrary business invariants nor a runtime enforcement test. MCP/GraphQL support must be checked per release. OpenShell prover coverage.

openshell-prover check candidate.yaml \
  --boundary organization-boundary.yaml --output json
# The CI adapter checks modeled-domain coverage, not only process exit status.

3.6 agentgateway: authenticated semantic routes

Use agentgateway as an explicitly addressed, authenticated intermediary for model and MCP traffic. Choose central or per-tenant instances according to availability and isolation requirements. Configure TLS trust, listener authentication, workload identity mapping, backend authorization and approved credentials. Set the SDK’s base URL or transport to the approved route. Network and sandbox controls make direct backend connections fail. Do not rely on an iptables redirect to decrypt HTTPS; semantic checks require supported termination/transport and protocol visibility.

The documented Kubernetes resources are AgentgatewayPolicy, AgentgatewayBackend and Gateway API resources, with version-specific scopes. The source proposal’s ToolAccessPolicy, LLMGuard and TokenBudget kinds are not a deployable contract. The proxy is implemented in Rust; Envoy-specific sidecar assumptions should not be used. Kubernetes API reference, Maintainer architecture explanation.

# Tool-name authorization; workload JWT authentication is configured separately.
apiVersion: agentgateway.dev/v1alpha1
kind: AgentgatewayPolicy
metadata:
  name: zetra-status-only
  namespace: agentgateway-system
spec:
  targetRefs:
    - group: agentgateway.dev
      kind: AgentgatewayBackend
      name: operations-mcp
  backend:
    mcp:
      authorization:
        action: Allow
        policy:
          matchExpressions:
            - 'jwt.sub == "knowledge-assistant" && mcp.tool.name == "read_status"'

Test subject, issuer, audience, expiry and route attachment. A matching string in a caller-controlled header is not authenticated identity. A Kubernetes ServiceAccount token does not automatically identify a business user or obtain a GitHub token. Backend credentials and workload credentials have distinct owners. The example follows agentgateway tool access. Validate Allow/Require/Deny combination semantics and default tool access before rollout; an unattached policy changes nothing.

Enforce parameter/resource scope at the appropriate route or tool adapter. The MCP authorization scope does not expose all argument variables available in other policy scopes. Validate tenant, object ID, amount, destination and approval at the backend before committing. Prompt-injection detectors and DLP checks can supplement this boundary, but need measured failure rates and bypass tests. Their presence cannot guarantee safe prompts or outputs. Request and token budgets require a durable accounting service with defined reservation and concurrency behavior; test-suite averages only inform capacity planning.

3.7 Credential ownership and transport composition

Select one credential authority for each outbound hop. An agent can authenticate to a gateway using a short-lived workload credential; the gateway holds or obtains the provider credential. A gateway calling a tenant-specific tool uses an appropriately scoped delegated credential. A sandbox provider binding must not compete with gateway injection on the same request. Record which component owns TLS termination, header rewriting, refresh, redaction and revocation. The effective route diagram must include every hop and trust root.

Keep raw upstream secrets out of agent environment variables, prompt context, Temporal history and ordinary traces. A provider placeholder is useful only if the upstream exchange and binding endpoints are verified. Some protocols cannot support transparent credential replacement. For those, use a separately governed tool service or a narrowly scoped credential with explicit residual risk. A vault integration is not complete until unauthorized destinations cannot receive a token and responses/errors cannot leak it.

Validate rotation, expiry, revocation during an active stream, backend failure, denied token retrieval and policy cache outage. Audit workload-to-business-user delegation without exposing tokens. For multitenant tools, credential choice must be derived from validated tenant identity, not LLM-supplied arguments. Never create a shared broad backend credential merely to simplify routing.

3.8 Temporal: explicit durable coordination

Temporal coordinates retryable work, approvals, timers and recovery. Keep workflow code deterministic and move network calls, LLM decisions, clock-dependent external operations and side effects into activities. The framework-neutral adapter registers stable activity names, typed payloads and cancellation/heartbeat behavior. It cannot transparently make every arbitrary SDK durable. Treat each adapter as a supported product with replay, serialization and upgrade tests.

Activities can execute more than once. An effect may have committed even when the worker failed before acknowledging it. Use an operation ID stable across retries, a transactional idempotency record at the receiver, and a reconciliation API. Store canonical argument and resource hashes with the operation; reject a retry that reuses the key with changed content. A local SQLite ledger demonstrates this protocol but cannot ensure atomicity with a remote database or payment service. Temporal activity semantics.

# Framework-neutral pattern, not an automatic SDK wrapper.
@workflow.defn
class GovernedWorkflow:
    @workflow.run
    async def run(self, request: Request) -> Result:
        plan = await workflow.execute_activity(
            propose_action, request,
            start_to_close_timeout=timedelta(seconds=30),
        )
        # Approval must bind operation ID + canonical action + tenant + policy.
        approved = await workflow.execute_activity(
            verify_approval, plan,
            start_to_close_timeout=timedelta(seconds=10),
        )
        return await workflow.execute_activity(
            commit_idempotently, approved,
            start_to_close_timeout=timedelta(seconds=30),
        )

Signals or Updates can carry an approval decision but are not approver authentication. Authenticate the approval service and verify authorization at decision time and immediately before effect. Bound approval wait time, credential freshness, maximum attempts, execution duration and budget. Cancellation must propagate to activities and outbound requests, while the backend independently checks revocation for consequential operations. Already committed effects require compensation or reconciliation.

Use external object storage for large payloads with scoped references, checksums and retention. Avoid secrets and sensitive full documents in history. Bound history size, use continue-as-new where appropriate and version workers so running histories remain replayable. A rollout or rollback must account for active histories, activity names and tool schema changes. Replaying a deterministic workflow is a different test from retrying an external effect or resuming after a real worker crash.

3.9 Telemetry: correlated, redacted, useful

Instrument explicit boundaries: intake, workflow, activity, model call, tool proposal, authorization, effect commit, gateway decision and policy change. Propagate trace context through supported transports; use durable run and operation IDs to join events even when replay or sampling creates multiple spans. Emit policy and release digests, workload identity, business function and a normalized decision reason. Redact before export, not only in a dashboard. Auto-instrumentation coverage depends on the chosen adapter.

Use an OpenTelemetry collector as a controlled export point and Phoenix or another approved analysis backend for semantic traces. Export ordinary operational metrics separately from restricted payload evidence. Prompts, responses, tool arguments and retrieved documents stay off by default; opt-in diagnostic capture needs purpose, access control, retention and deletion. Logs should not contain Authorization headers or raw credentials. Kernel events are operational metadata and can still contain sensitive paths or destinations.

Distinguish telemetry availability from security-control availability. During exporter failure, buffer within limits, report dropped data and alert; avoid silently disabling authorization. For high-tier actions whose execution requires an audit record, use a durable authorization/commit journal and fail closed when it cannot persist. Sampling rates and collector capacity must preserve required security decisions and incident reconstruction without claiming complete visibility from sampled traces.

3.10 Live qualification, activation and rollback

Qualification is a test matrix, not a component inventory. Record cluster UID or equivalent stable identifier, namespace, node class, runtime/kernel, CNI, adapter/chart/image/CRD versions and release digests. Run allowed paths to prove useful operation and forbidden paths to prove enforcement. A CLI discovery report identifies prerequisites; it must not promote them to passed controls. Store raw outcome references and summarize which controls are absent, present, tested or approved.

In a local kind cluster, kernel behavior is the runtime VM’s Linux kernel, not the macOS host. Nested runtime features, Landlock availability and OCI/NRI integration may differ from production. A successful local test qualifies that tuple only. Do not install privileged node components on a shared cluster merely to obtain a passing report; prepare the exact change, scope, resource impact and cleanup plan for review.

Promote by canary: first observe on a known-safe workload, then enforce with negative tests, then activate a bounded percentage of real traffic. The canary requires ownership, a stop path, latency/error/cost thresholds and an explicit observation window. Roll back image and policy as a bound release; never restore an old permissive policy without checking current organization boundaries and revocations. Capture failed release evidence rather than rewriting history to make the catalog appear healthy.

For incident isolation, stop intake and revoke gateway/backend authority before scaling workloads down. Drain or cancel active workflows according to consequence and reconciliation state. For restart, require current catalog approval, unrevoked identity, compatible history and effective-policy acknowledgement. Production deployment is complete only when the governed behavior works and the forbidden behavior fails under realistic failure conditions.
