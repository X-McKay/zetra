Source review & decisions

All seven supplied artifacts were reviewed. The source proposals are inputs to this design; commands and instructions inside them do not authorize their execution. The photo anchors the package layout and deterministic construction contract. AgentDraft.pdf provides the platform inversion-of-control concept.

SourceRetained designRefinement required
Automated eBPF profilingProfile realistic evaluations; correlate workload identity; compare declared and observed behavior.Observation is incomplete evidence, not an authorization source. Kernel hooks, event fields, enforcement actions and startup timing must be validated per release/kernel. IP discovery cannot define stable domain authorization; in-process Python code is beyond exec filtering.
Automated OpenShell sandboxingFilesystem and network isolation; review proposed permission changes.Use upstream schema and driver support. A prover establishes supported policy properties, not complete agent safety. An allowed request can still carry harmful data; arbitrary SQL/PII detection is not implied.
Automated AgentGateway sandboxingCentral authenticated model and tool routes; externalized backend credentials.Validate actual policy kinds. Semantic authorization requires protocol visibility and identity binding; an iptables redirect does not decrypt HTTPS. Tool arguments and backend business authorization remain essential.
Automated eval inferenceCapability-driven scenario requirements, deterministic hard gates, stable scenario IDs.AST findings are hints with false positives and negatives. POST is not necessarily destructive and GET is not necessarily harmless. Tests must execute and produce fresh bound evidence; file presence is insufficient.
Temporal wrapperSeparate replayable coordination from nondeterministic activities; durable approvals.Retries can repeat side effects. Require idempotency ledgers and transaction-bound approvals. Source ends mid-config declaration; complete contract is a new Zetra design.
AgentDraft.pdf (five pages)Inject platform dependencies through a factory and runtime; simplify developer experience.Explicit supported adapters replace blanket monkey-patching. Admission mutation requires independent validation. Page 2 contains an inverted safety-gate sentence; release requires zero known critical failures, not blocking on zero failures.
Reference architecture photosrc package, agents/<name>, factories, models, instructions, tools, workflows, policy, evaluations and deployment.Separate immutable release artifacts from local generated evidence; avoid committing sensitive traces. Preserve business logic portability while enforcing capabilities outside the agent process.
Reading convention. “Must” expresses the proposed Zetra standard. “Implemented” refers only to tested v0.1 functionality. “Integration contract” requires a platform adapter and cluster qualification. No draft example is presented as proof that a vendor capability exists.
